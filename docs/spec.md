# Часть 0. Данные

## Теория

Любая рекомендательная система начинается с **лога взаимодействий**: «кто — что — когда». У нас это `ratings.csv`.

Если представить его как матрицу «пользователи × фильмы», почти все клетки пустые: каждый видел крошечную долю каталога. Это **разреженность**.

**Длинный хвост**: небольшая доля фильмов собирает большинство оценок, а огромное количество фильмов оценено единицами. Популярное угадать легко, редкое — трудно.

**Среднее обманывает**: фильм с одной оценкой 5.0 окажется «лучшим». Честнее **взвешенный рейтинг**:

```
WR = v / (v + m) · R  +  m / (v + m) · C
```

`R` — средняя оценка фильма, `v` — число его оценок, `C` — средняя по всем фильмам, `m` — порог доверия. Мало оценок → WR близок к C; много → к R.

**Время** важно всегда: пользователи приходят и уходят, фильмы выходят, вкусы меняются.

# Часть 1. Первая рекомендация и честная проверка

## Теория

**Рекомендация** — список из K фильмов, без уже просмотренных.

Самая простая — **популярное**. Она не персональная, но сильная: хиты нравятся многим. Любая умная модель обязана её обыгрывать.

**Почему делим по времени.** Если разделить данные случайно, модель будет учиться на будущем и проверяться на прошлом. В жизни мы всегда предсказываем будущее по прошлому:

```
────────── train ──────────┤── val ──┤── test ──┤
```

- на train учим, на val подбираем настройки;
- финал: учим на train + val, **один раз** проверяем на test.

Правила проверки:
- проверяем **тёплых** пользователей — с историей до окна;
- **релевантные** — фильмы, оценённые в окне на 4.0+;
- уже просмотренное до окна не считается ни рекомендацией, ни попаданием.

**Метрики** (K = 10), считаются по каждому пользователю и усредняются:
- **HitRate@K** — угадали ли хоть что-то (0 или 1);
- **Precision@K** — доля угаданных среди K;
- **Recall@K** — доля угаданных среди релевантных, делим на `min(релевантных, K)`.

# Часть 2. Метрики порядка

## Теория

Precision и Recall не различают, где стоит угаданный фильм. Но пользователь смотрит в основном на верх списка.

**MAP@K**: в каждой позиции с попаданием считаем precision до неё и усредняем.

```
выдача [A, B, C], релевантные {A, C, D}, K = 3
позиция 1: попадание, precision = 1/1
позиция 3: попадание, precision = 2/3
AP@3 = (1 + 2/3) / min(3, 3) = 0.556
```

**NDCG@K**: попадание на позиции `i` стоит `1 / log2(i + 1)` (1, 0.63, 0.5, …). Сумма — DCG, делим на лучшую возможную сумму:

```
DCG  = 1 + 0 + 0.5       = 1.5
IDCG = 1 + 0.631 + 0.5   = 2.131
NDCG = 1.5 / 2.131       = 0.704
```

Помимо точности важно, **что** рекомендуем:
- **Coverage@K** — доля каталога, которая хоть раз попала в чьи-то рекомендации;
- **Novelty@K** — среднее `−log2(доля пользователей, смотревших фильм)`: хиты дают мало, редкие фильмы много.

# Часть 3. Похожие фильмы (ItemKNN)

## Теория

Идея: **«тем, кто смотрел это, понравилось и то»**.

Фильм — вектор длиной «число пользователей», единицы у тех, кто его смотрел. Два фильма похожи, если их смотрят одни и те же люди. Мера — **косинус**:

```
sim(i, j) = (смотрели оба) / (√(смотрели i) · √(смотрели j))
```

Скор кандидата для пользователя — сумма его сходств с просмотренными фильмами:

```
score(u, j) = Σ sim(i, j)   по фильмам i из истории u
```

В матричном виде: `scores = X[u] @ S`, где `S` — матрица сходств.

Практика:
- матрица пользователи × фильмы хранится в `scipy.sparse.csr_matrix`, нужны маппинги `movieId ↔ номер столбца`;
- для каждого фильма оставляем только **топ-k соседей** — главный параметр модели;
- редкие фильмы (порог `min_count`) отсекаем, их сходства случайны;
- полная матрица 62 тыс. × 62 тыс. не влезет в память — считаем кусками и из каждого куска берём топ-k.

# Часть 4. Скрытые вкусы (ALS и EASE)

## Теория

Представим, что у фильма есть скрытые характеристики («фантастика», «авторское кино», «для семьи»), а у пользователя — насколько они ему нравятся. Интерес — скалярное произведение:

```
score(u, i) = вектор_пользователя · вектор_фильма
```

Модель сама подбирает векторы длины d так, чтобы произведения совпадали с данными:

```
X  ≈  P · Qᵀ
(пользователи × фильмы) ≈ (пользователи × d) · (d × фильмы)
```

Векторы фильмов — **эмбеддинги**: похожие фильмы получают близкие векторы.

**ALS для неявных данных.** «Не смотрел» не значит «не понравилось». Поэтому учим на всех клетках, но с разным весом:
- взаимодействие — цель 1, вес `1 + alpha · сила`;
- пустая клетка — цель 0, вес 1.

Если зафиксировать векторы фильмов, векторы пользователей находятся формулой линейной регрессии; потом наоборот. Чередуем 15–30 раз — отсюда «alternating least squares».

Параметры: `factors`, `regularization`, `alpha`, `iterations`.

**EASE.** Учится матрица весов «фильм → фильм», чтобы строка пользователя предсказывалась через саму себя (с запретом на диагональ). Похоже на ItemKNN, но веса выученные. Решается одной формулой через обращение матрицы «фильмы × фильмы», поэтому только на ограниченном числе фильмов.

## Задачи

Метод `similar_items`, как в ItemKNN; проверь те же 5 фильмов.

**4.3. Подбор ALS.** На val: `factors`, `regularization` (лог-сетка), `alpha`, `iterations`, минимум 30 запусков. Лучшее → test.

**4.5. EASE.** `recsys/models/ease.py`, параметры `lam`, `n_items`:

```python

G[np.diag_indices_from(G)] += lam
P = np.linalg.inv(G)
B = P / (-np.diag(P))
B[np.diag_indices_from(B)] = 0
scores = X @ B
```

**До запуска** посчитай память G для 5, 10, 15, 20 тыс. фильмов и выбери `n_items`. Подбери `lam` на val. Лучшее → test.

# Часть 5. Контент и новые фильмы

## Теория

Модели выше знают о фильме только, **кто его смотрел**. Новый фильм без оценок они никогда не порекомендуют. Это **холодный старт**.

# Часть 6. Двухэтапная система

## Теория

Реальные сервисы работают **воронкой**:

1. **Кандидаты**: быстрые модели отбирают 100–200 фильмов из всего каталога.
2. **Ранжирование**: градиентный бустинг сортирует их с учётом множества признаков.

Бустинг знает много, но медленный; простые модели быстрые, но знают мало. Вместе — лучшее из двух.

**Ранжировщик не поднимет фильм, которого нет среди кандидатов**, поэтому первый этап оценивают через Recall@100/200 — это потолок системы.

**Learning to rank**: для каждого пользователя есть группа кандидатов, их нужно отсортировать. В CatBoost — лосс `YetiRank` и `group_id` (строки одного пользователя подряд).

**Откуда метки** — ещё одно окно:

```
──── окно A ────┤── окно B ──┤── test ──┤
```

- генераторы учатся на A;
- метка кандидата = 1, если в B пользователь оценил его на 4+;
- признаки — **только по A**;
- для test всё сдвигается: генераторы и признаки — по A + B.

**Признаки:** скоры и места от генераторов; фильм (популярность за периоды, средняя оценка, год, жанры); пользователь (активность, средняя оценка, давность); пара (частота жанра в истории, контентная близость).

**Главная ловушка — утечка**: признак, посчитанный по всем данным, содержит ответы из окна B.

## Задачи

**6.1. Окна.** В `config.py` — границы A и B. В `split.py` — `get_ranking_split()`, возвращающий историю A, окно B и данные для test.

**6.2. Кандидаты.** `recsys/candidates.py`: `generate_candidates(models: dict, history, user_ids, n)` → DataFrame `user_id, item_id, {model}_score, {model}_rank` (`NaN`, если фильм не пришёл от модели). **6.4. Модель.** `recsys/models/two_stage.py`: `TwoStageRecommender(generators, n_candidates, ranker_params)` с тем же интерфейсом `BaseRecommender`:
- `fit(history)`: сам делит history на A и B, учит генераторы на A, строит кандидатов и признаки, ставит метки по B, убирает пользователей без позитивов, делит пользователей 80/20 для ранней остановки, учит `CatBoostRanker`, затем **переобучает генераторы на всей history**;

# Часть 7. Нейросеть с двумя башнями

## Теория

**Two-tower** — нейросетевой генератор кандидатов:
- **башня пользователя**: последние просмотренные фильмы → усреднение эмбеддингов → MLP → вектор `u`;
- **башня фильма**: id (и, по желанию, контент) → MLP → вектор `v`.

Скор — `u · v`. Башни независимы, поэтому векторы фильмов считаются заранее и кладутся в индекс **Faiss**. В момент запроса — только вектор пользователя и поиск ближайших, как в RAG.

**Обучение**: пример — (история до момента t, фильм в момент t). **In-batch negatives**: для каждой пары в батче негативы — фильмы остальных пар:

```python
logits = U @ V.T / tau
loss = F.cross_entropy(logits, torch.arange(B))
```

**logQ-коррекция**: популярные фильмы слишком часто становятся негативами, модель их занижает. Исправление:

```python
logits = U @ V.T / tau - torch.log(item_freq[batch_items])
```

## Задачи

**7.1. Датасет.** `recsys/nn/datasets.py`: `NextItemDataset` отдаёт `(history: LongTensor[L], target)` — для оценки ≥ 4 в момент t последние L фильмов строго до t, паддинг нулём, id сдвинуты на 1. Индексы фильмов — из `InteractionMatrix`.

**7.2. Сеть.** `recsys/nn/two_tower.py`: две башни, усреднение с маской паддинга, L2-нормировка выходов.

**7.3. Модель.** `recsys/models/two_tower.py`: `TwoTowerRecommender(dim, history_len, tau, logq, epochs, ...)`:
- `fit`: цикл обучения, лог loss;
- `recommend`: вектор пользователя по последним L фильмам history → `faiss.IndexFlatIP` → топ-K без просмотренного.

**7.4. Эксперимент.** Раздел «Часть 7»: кривые loss и Recall@10 на val по эпохам; сравнение с `logq=True` и `False` по точности, покрытию и новизне; время Faiss против точного перебора. Итог на test.

**7.5. В воронку.** Добавь two-tower в генераторы `TwoStageRecommender`. Как изменились Recall@200 кандидатов и итоговый NDCG@10?

# Часть 8. Последовательности (SASRec), бонус

## Теория

Все модели выше смотрят на историю как на **набор**. Но порядок важен: после первой части смотрят вторую, вкусы дрейфуют.

**SASRec** — маленький GPT для фильмов:
1. последние L фильмов по времени;
2. эмбеддинг фильма + эмбеддинг позиции;
3. блоки трансформера с causal-маской;
4. выход на позиции t сравнивается со всеми фильмами, цель — фильм t + 1.

Учится сразу по всем позициям, для рекомендации берётся последняя. Важно: с полной кросс-энтропией по всем фильмам модель заметно сильнее, чем с одним случайным негативом, как в оригинальной статье (Klenitskiy & Vasilev, 2023).

## Задачи

**8.1. Датасет.** В `recsys/nn/datasets.py`: `SequenceDataset` — вход `seq[:-1]`, цель `seq[1:]`, паддинг слева.

**8.2. Сеть и модель.** `recsys/nn/sasrec.py` (эмбеддинги, позиции, `nn.TransformerEncoder` с causal- и padding-масками, выход через матрицу эмбеддингов фильмов) и `recsys/models/sasrec.py` с интерфейсом `BaseRecommender`.

**8.3. Эксперимент.** Полная кросс-энтропия, паддинг вне лосса, `history_len` из `[50, 100, 200]` на val. Итог на test.
